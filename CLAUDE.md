## What This Project Is

`model_serve` is a Python-based multi-backend LLM serving stack. It wraps [llama-swap](https://github.com/mostlygeek/llama-swap) and Ollama behind a single OpenAI-compatible API endpoint (port 5846). The central orchestrator is `harmony_proxy.py` — a FastAPI async proxy that routes requests to the right backend and handles Harmony encoding for GPT-OSS models.

## Common Commands

```bash
# Server control
./model start           # Start everything (harmony_proxy, llama-swap, sync_loop, pressure_unloader)
./model stop            # Stop all services
./model status          # Check what's running
./model stats           # Show loaded models + memory usage

# Model management
./model pull <name>     # Pull via Ollama and auto-sync config
./model rm <name>       # Remove and auto-sync
./model list [filter]   # List Ollama models
./model list --config   # List llama-swap model names (use these in API calls)
./model names [filter]  # Show Ollama → llama-swap name mapping (important: names differ)
./model show <filter>   # Show full generated config for matching models
./model sync            # Regenerate config.yaml without restarting

# Tests
cd /Users/au/src/model_serve
python -m pytest tests/ -v
python -m pytest tests/test_harmony_proxy.py::test_name -v  # single test

# Install dependencies
pip install -r requirements.txt
```

## Architecture

```
Client (port 5846)
    └── harmony_proxy.py (FastAPI)
            ├── GPT-OSS / Harmony models  → llama-swap (port 5847)   [with Harmony encode/decode]
            ├── MXFP4 models              → Ollama (port 11434)       [llama.cpp can't do MXFP4]
            ├── Embedding models          → Ollama                    [models with "embed" in name]
            ├── lm_studio backend         → LM Studio (port 1234)
            └── All other models          → llama-swap (port 5847)    [passthrough]
```

**Key files:**
- `harmony_proxy.py` — the main proxy (64KB, handles routing, Harmony encode/decode, streaming, tool calls)
- `generate_config.py` — scans `MODELS_DIR/ollama/` for GGUF files, merges `custom_models.yaml`, writes `config.yaml`
- `pressure_unloader.py` — background daemon; polls llama-swap `/running` and Ollama `/api/ps`; evicts LRU idle model when memory exceeds threshold
- `model` — CLI script (Python); wraps ollama pull/rm, triggers sync, controls services
- `config.yaml` — **auto-generated**, do not edit manually; regenerated by `./model sync`
- `custom_models.yaml` — per-model overrides merged into `config.yaml` (sampler_args, ctx_size, ttl, backend, base_model, etc.)
- `harmony_models.yaml` — list of model names that require Harmony encoding (checked at startup)
- `lm-studio-ollama-bridge/` — Go submodule; creates symlinks from Ollama blob store into `MODELS_DIR`

## Model Names vs Config Names

Ollama names (`gemma3:27b`) differ from llama-swap names (`gemma3:27.4b-q8_0`) because llama-swap uses GGUF file metadata. Always use `./model names` or `./model list --config` to find the correct name for `custom_models.yaml` keys and API requests. The `MODEL_PREFIX` (`ms/` by default) is prepended to all llama-swap model names.

## Harmony Encoding

GPT-OSS models require Harmony encoding — a custom format that maps OpenAI message structure to a raw-text prompt format. The proxy uses the `openai-harmony` Python package. Models listed in `harmony_models.yaml` go through encode/decode; everything else passes through unchanged. Streaming Harmony responses are accumulated token-by-token in `HarmonySessionState` and re-emitted as OpenAI SSE events.

## Config Precedence

1. Auto-discovered GGUF files in `MODELS_DIR/ollama/` → base config
2. Entries in `custom_models.yaml` → merged/overridden per model
3. `base_model:` key → create alias that shares the same GGUF but with different settings
4. `backend: ollama` or `backend: lm_studio` → skip llama-swap entirely for that model

## Environment

All runtime config comes from `.env` (copy `.env.example`). Key variables: `HARMONY_PROXY_PORT` (5846), `LLAMA_SWAP_PORT` (5847), `OLLAMA_BASE`, `MODEL_TTL`, `MEMORY_PRESSURE_THRESHOLD`, `MODELS_DIR`, `MODEL_PREFIX`. Never hardcode these values in code.

## Testing Notes

Tests import directly from `harmony_proxy.py` — the test runner must be launched from the project root so Python can resolve the module. Tests use `pytest`; no test database or external services required for unit tests (mocked with pytest fixtures).
